# Realistic Water Implementation Plan

This document defines the implementation sequence for improving
`Market/World/RealisticWater`. It is a technical design and verification guide, not a progress
log. Live progress remains in `dev_plan_4_1.md`.

Related references:

- `RealisticWater.shader` contains the implementation and its local design intent.
- `SHADERS.md` contains the shader inventory, dependencies, known limitations, and iteration
  workflow.
- `CHANGELOG.md` records completed work.
- `Artifacts/RealisticWater/R0/baseline.md` is the generated local baseline report.

## Goal

Produce convincing PC water for the project while keeping the system understandable, measurable,
and safe to integrate. Realism should come from coherent wave motion, physically plausible light
transport, useful local reflections, and temporal behavior rather than hidden color tricks.

The experimental shader remains isolated to `WaterShaderLab.unity` until an explicit promotion
decision is made. `MarketWater.shader` and the shipped Island water remain unchanged during this
track.

## Non-goals

- Do not begin with an FFT ocean or an unbounded number of wave samples.
- Do not enable project-wide renderer features without a measured GPU comparison.
- Do not replace the Island water before the lab result passes visual and performance gates.
- Do not combine underwater rendering, persistent foam, and reflection infrastructure into one
  shader-only change.
- Do not treat Editor Play Mode numbers as standalone-build performance guarantees.

## Fixed verification conditions

Use `Market/Debug/Water/Capture R0 Baseline` before and after each material shader stage.

The command captures:

1. `01_elevated_overview.png` for depth color, caustics, wave scale, and broad composition.
2. `02_shoreline_detail.png` for refraction, shoreline foam, intersections, and shallow water.
3. `03_horizon_aliasing.png` for distant normals, specular stability, and wave silhouette.

The performance sample uses the elevated view at 1280x720, a 2 second warmup, and an 8 second
measurement window. Compare average, p95, maximum, and frames over 16.67 ms. The report must retain
the Unity version, GPU, graphics API, shader/material hashes, and material snapshot.

The current R0 reference was measured in Unity 6000.5.3f1, Direct3D12, on an NVIDIA GeForce RTX
5060:

- Observed frame time: 1.61 ms average, 1.90 ms p95.
- CPU frame time: 1.61 ms average, 1.90 ms p95.
- GPU frame time: 0.43 ms average, 0.43 ms p95.
- Frames over 16.67 ms: 0.

These values are a comparison anchor for this machine and Editor session only.

## Shared implementation rules

- Change one major visual subsystem per stage.
- Preserve current material behavior unless the stage explicitly migrates it.
- Update `M_RealisticWaterLab.mat` or `RealisticWaterMaterialInstaller` when serialized material
  values must change. Shader defaults do not overwrite existing material values.
- Keep all code, comments, UI text, asset names, and documentation ASCII English.
- Isolate the term under review by temporarily setting unrelated material strengths to zero.
- Verify elevated, shoreline, and horizon views. One view cannot validate the whole shader.
- Run `Assets/Refresh` after new assets, then recompile and require Unity health `ok`.
- Record the completed stage in `CHANGELOG.md`.
- Keep the scene clean after captures and benchmarks.

## R0 - Reproducible baseline

Purpose: establish a stable comparison target before changing the shader.

Implementation:

- Provide three named, fixed camera views at 1280x720.
- Snapshot the material values and shader/material dependency hashes.
- Measure a fixed elevated view in Editor Play Mode.
- Store generated output under the git-ignored `Artifacts/RealisticWater/R0/` folder.
- Restore the edit-mode camera, label state, Play Mode state, and scene cleanliness.

Acceptance:

- Three readable PNG files and `baseline.md` are generated by one menu command.
- CPU and GPU values are recorded when `FrameTimingManager` supplies them.
- Missing timing data is reported as unavailable, never estimated.
- The shader, material, and scene remain unchanged.

## R1 - Physically coherent wave motion

Purpose: replace independently tuned sine motion with waves that share a coherent physical model.

Implementation:

1. Keep the initial four-wave budget so optical and motion changes remain separable.
2. Use deep-water dispersion:

   `k = 2 * PI / wavelength`

   `omega = sqrt(gravity * k)`

   `phase = k * dot(direction, worldXZ) + omega * time * speedMultiplier`

3. Preserve each `_WaveNParams.w` value as a dimensionless speed multiplier during migration rather
   than silently changing or deleting serialized material data.
4. Add a normalized wind direction and directional spread control. Wave directions should cluster
   around the wind while retaining enough crossing energy to avoid parallel ridges.
5. Constrain effective steepness from wavelength, amplitude, and wave count so the horizontal map
   does not unintentionally fold.
6. Derive position tangents, binormals, and the macro normal from the same Gerstner derivatives.
   Avoid maintaining a visually unrelated normal approximation.
7. Keep the horizontal Jacobian output because later foam stages use it.
8. Add an optional frozen diagnostic time only if repeatable wave phase proves necessary. It must
   default off and have zero release cost.

Expected property work:

- Add `_WindDirection`.
- Add `_WindSpread`.
- Add `_Gravity` only if a fixed physical constant is too restrictive for art direction.
- Retain `_Wave1Params` through `_Wave4Params` for material compatibility.
- Clarify in the Inspector that the fourth vector component is a speed multiplier.

Acceptance:

- Long waves move more slowly in phase than short waves according to the dispersion relationship.
- Macro normals remain attached to displaced geometry at crest and trough extremes.
- Default waves do not create inverted triangles, holes, or uncontrolled fold artifacts.
- The horizon silhouette has coherent groups rather than four visibly independent sine bands.
- Jacobian foam input still covers the expected numeric range.
- R0 captures and performance are recorded before and after the stage.

## R2 - GGX surface lighting

Purpose: replace the legacy power-based sun glint with a physically plausible water BRDF.

Implementation:

1. Replace `pow(NdotH, _SpecPower)` with a GGX normal distribution.
2. Use Schlick Fresnel with water `F0` near 0.0204.
3. Use Smith correlated visibility or an equivalent stable masking-shadowing term.
4. Enforce energy conservation between reflection and transmission.
5. Use roughness consistently for direct sun and environment reflection.
6. Clamp denominators and dot products so grazing angles cannot create NaN or white fireflies.
7. Keep main-light shadow attenuation on direct sun reflection, but do not multiply environment
   reflection by the main-light shadow.
8. Remove `_SpecPower` only after the material installer and existing material are migrated.

Acceptance:

- The sun highlight broadens smoothly with roughness.
- No white fireflies appear on back-facing or grazing wave facets.
- Head-on reflection remains subtle and grazing reflection remains strong.
- Shadows do not alter water depth or transmission.
- The horizon capture remains temporally stable.

## R3 - Spectral absorption and in-scattering

Purpose: make shallow and deep water differ through light transport rather than a scalar color lerp.

Implementation:

1. Reconstruct the opaque scene position at the validated refracted UV.
2. Compute view-ray distance through the water instead of using only vertical depth for optical
   extinction.
3. Introduce RGB absorption coefficients.
4. Calculate transmittance per channel:

   `T = exp(-absorptionCoefficient * pathLength)`

5. Compose the refracted scene with a controlled in-scattering color:

   `transmission = sceneColor * T + scatteringColor * (1 - T)`

6. Retain a separate vertical-depth value for shoreline masks where vertical water depth is the
   useful quantity.
7. Handle missing depth, sky depth, reversed Z, and invalid reconstructed positions explicitly.

Expected property work:

- Replace or reinterpret `_DepthFadeDistance` only through an explicit material migration.
- Add `_AbsorptionCoefficients`.
- Add `_ScatteringColor`.
- Add `_ScatteringStrength` if color alpha is not used for strength.

Acceptance:

- Sand remains readable through shallow water without a milky white overlay.
- Red light attenuates before blue-green light with increasing path length.
- Deep water converges smoothly toward the selected scattering color.
- Oblique views show greater extinction than top-down views through the same vertical depth.
- No discontinuity appears when refraction falls back to the original screen UV.

## R4 - Natural micro-normal detail

Purpose: remove the visibly procedural crossed-sine ripple pattern.

Implementation:

1. Author or generate two seamless water normal maps with mipmaps.
2. Sample them in world space with different scales, speeds, and wind-aligned directions.
3. Blend normals with a reoriented or derivative-safe method rather than direct component addition.
4. Retain distance-based detail fade.
5. Reduce normal strength as a function of projected pixel size to avoid far-water shimmer.
6. Keep texture sampling count and anisotropic filtering measurable.
7. Provide a texture-free fallback only if it is required by a lower quality tier.

Expected property work:

- Add two normal textures.
- Add per-layer tiling and speed.
- Retain `_MicroWaveStrength` as the top-level detail amplitude when practical.
- Replace `_MicroWaveTiling` and `_MicroWaveSpeed` through a documented migration.

Acceptance:

- No obvious periodic diagonal grid is visible in the elevated view.
- Close ripples follow wind direction without sliding across macro crests.
- Distant water loses micro detail before it becomes sub-pixel noise.
- Horizon p95 and maximum frame time do not regress beyond the agreed stage budget.

## R5 - Reflection and refraction integration

Purpose: make the surface respond to nearby world geometry without unsafe global renderer cost.

Implementation:

1. Clamp or reject refracted UV outside the valid screen region.
2. Fade distortion near screen edges.
3. Scale refraction distortion by water thickness so thin shoreline water does not bend the scene
   more than deep water.
4. Keep the foreground-geometry rejection test and harden it for reversed Z and steep displaced
   waves.
5. Compare local reflection options:
   - screen-space reflection with sky fallback;
   - one bounded planar reflection for the lab;
   - sky-only reflection for the lowest quality tier.
6. Measure every renderer feature separately.
7. Do not enable a global opaque-color copy or project-wide reflection feature for Island without
   a before/after GPU capture.

Acceptance:

- No smear, wrap, or black border appears at screen edges.
- Rocks and shore geometry do not appear refracted when they are in front of the water.
- Reflection fallback transitions do not flash.
- The selected local-reflection path has a documented GPU cost and quality fallback.

## R6 - Temporal whitecaps and shoreline foam

Purpose: make foam persist, move, and decay instead of appearing only from the current-frame mask.

Implementation:

1. Keep the Jacobian and shoreline masks as foam injection sources.
2. Create a bounded world-space foam accumulation texture.
3. Update it with decay, injection, and wind or flow advection.
4. Reproject or reset safely when the tracked water region moves.
5. Sample accumulated foam in the surface shader.
6. Separate whitecap and shoreline tuning so one cannot hide the other.
7. Add depth-gradient and obstacle-intersection breakup to the shoreline term.
8. Provide a no-history fallback quality tier.

Acceptance:

- Whitecaps remain briefly after a crest starts flattening.
- Foam moves coherently instead of sticking to screen pixels.
- Shoreline foam forms a broken band, not a solid white shelf.
- The accumulation buffer has explicit resolution, world coverage, memory, and GPU cost.
- Camera movement does not smear, erase, or duplicate foam unexpectedly.

## R7 - World-space caustics

Purpose: make caustics behave like projected light on submerged geometry.

Implementation:

1. Move caustic projection out of the surface color composite when necessary.
2. Project in world space using the main-light direction.
3. Animate two or more patterns without visible texture swimming.
4. Attenuate caustics by depth, water turbidity, sun angle, and main-light shadow.
5. Apply the effect to submerged terrain and props through a bounded renderer pass, decal, or
   equivalent measured approach.
6. Keep a cheap surface-composite fallback if the projected path is too expensive.

Acceptance:

- The pattern remains attached to the seabed while the camera moves.
- Rocks and terrain receive consistent caustic scale.
- Caustics disappear smoothly with depth and in shadow.
- The effect does not brighten objects above the water surface.

## R8 - Underwater surface and volume

Purpose: make the transition through the surface and the view from below visually coherent.

Implementation:

1. Keep `UnderwaterFogController` responsible for the surrounding volume unless a dedicated volume
   system replaces it.
2. Add an optional underside surface path with front-face culling.
3. Invert or rebuild the normal correctly for the underwater view.
4. Model strong internal reflection at grazing underwater angles.
5. Blend the transition around the camera crossing the water height to avoid one-frame popping.
6. Benchmark the extra pass and keep it disabled in quality tiers that require front-face-only
   water.

Acceptance:

- The water surface is readable from below.
- Crossing the surface does not flash, invert color, or expose a missing frame.
- Underwater fog, absorption, caustics, and surface color share compatible parameters.
- The additional pass has an explicit performance cost and fallback.

## R9 - Quality tiers, optimization, and promotion gate

Purpose: turn the laboratory result into a controllable production candidate.

Implementation:

1. Define at least two quality tiers:
   - High: local reflections, persistent foam, projected caustics, and underwater surface.
   - Low: sky reflection, instantaneous foam, surface-composite caustics, and front-face-only
     rendering.
2. Remove unused shader variants and orphaned properties after material migration.
3. Profile vertex cost, fragment cost, opaque texture cost, reflection cost, and auxiliary buffer
   cost independently.
4. Test at the same camera, resolution, quality, and graphics API as R0.
5. Run a standalone development build capture before any Island promotion.
6. Compare the candidate against the existing `MarketWater.shader` on readability, style fit,
   performance, and maintenance cost.
7. Promote only through an explicit decision. Keep both shaders independent until then.

Acceptance:

- Unity compilation and health are green with zero console errors and no dirty scenes.
- Representative outdoor p95 remains below 16.67 ms.
- No visible camera-turn spikes appear.
- The shader works with the intended PC URP configuration.
- The production material, installer, scene builder, and documentation agree on every property.
- Rollback to `MarketWater.shader` remains simple and does not require scene reconstruction.

## Per-stage execution template

Use this sequence for R1 through R9:

1. Run the R0 command and preserve the generated report and three captures for comparison.
2. Confirm the active scene is `WaterShaderLab` and clean.
3. Change one subsystem and its material migration.
4. Refresh assets when required.
5. Recompile and require Unity health `ok`.
6. Isolate the changed visual term with temporary material values.
7. Inspect elevated, shoreline, and horizon views.
8. Restore intended material values.
9. Run the R0 command again and compare frame-time statistics.
10. Record the completed work and verification in `CHANGELOG.md`.

## Recommended next implementation

Begin with R1 only. Preserve the four current material wave vectors, reinterpret their speed
component as a multiplier over physically derived angular frequency, add wind direction/spread,
and derive the displaced surface normal from the same Gerstner derivatives. Do not combine R1 with
GGX, new normal textures, or foam history.
